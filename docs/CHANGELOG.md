## [Unreleased]

### Added
- **`F2.WS.09` — `cargo xtask bench-t0` measures the tiers that exist at this shape.** Four legs, each carrying its sample count, because a p999 over a hundred samples is the maximum wearing a percentile's name. Over 100 000 samples: an unsupervised `openat` at 1.80 µs p99, **T1** — the held syscall answered by the supervisor with no human — at **46.6 µs** p99 against a budget of 400/1000, the T2 path with a scripted answer at 39.3 µs, and **T0 at L2** — Landlock's deny, with no supervisor woken — at **2.42 µs** against 12/20. The in-kernel deny costs **19× less** than the supervised round trip, which is §2.2.1's argument in figures. The specified disclaimer was corrected before it shipped: it would have printed that no decision is taken in kernel, while `budgets.toml` defines L2's T0 as Landlock and plan `:1768` labels it the same way — so it would have hidden a budgeted figure behind a disclaimer. T0 at L3 and T-tel are printed as absent, never as zero. The probe is `aisme-agentsim --open-bench`, which times from inside the session because only the caller can time a held syscall.
- **`F2.WS.10` — `cargo xtask test-skeleton` runs the whole slice with no kernel, in 69 ms.** It orchestrates the shipped binaries instead of rebuilding the slice: the policy is compiled by the same `parse` + `compile` the daemon and the loader use, the daemon composes itself as it always does, and the WAL is read back by `aisme-forensicd --tail` as a second process, because a record surviving its writer is a two-process property. The one product change is `aisme-agentd --trace <file>`, a recording in the wire layout replayed through the composition root's own `MockSensor` — which is also the input `F0.ASSET.02`'s reference trace needs. It asserts neither correlation precision and recall (F5's `test-correlation`) nor zero hot-loop allocations (`F1.RT.03`'s `bench-hotloop`): a gate that claims another phase's property reports what it did not test. The command fails itself if it exceeds one second, so "in milliseconds" is measured and not claimed.
- **Session cgroups are released when they empty, and every session registers.** `aisme run` sends the cgroup it created and `agentd` waits on `poll` of `cgroup.events` for the kernel to say the session is empty, then removes the directory. No sweeper and no interval: a sweeper either runs too often or leaves a window, and cannot tell a new empty session from a finished one. Measured: 22 directories had accumulated on the development machine, one per run since `F2.WS.08`; afterwards an instant command is released, a filtered session supervises and then releases, and a four-second one is **present while it runs** and gone after — the case that gives the other two meaning. The seccomp listener became optional and `trapping` says on the wire which sessions installed a filter, so an unfiltered session is watched rather than invisible while a filtered registration without its listener is still refused. The `cgroup` parameter is bounded to `aisme-<16 hex>` under `/sys/fs/cgroup`, which is what stops the daemon ever being asked to remove a slice, a scope or the delegated root.
- **`F2.WS.11`'s write scope is denied in kernel.** `aisme run` builds one Landlock ruleset from the session's declared scope and applies it before `exec`, so the supervised command inherits a domain it cannot widen. Measured at ABI 9 through the shipped binary: `touch` outside the scope returns `EACCES` and the file is not created, inside it succeeds. It is applied **before** the seccomp filter and not after, because `landlock_add_rule` needs an `O_PATH` descriptor per allowed directory and building the ruleset under a filter that traps every `openat` would send the session's own setup to the supervisor, which `I-28` requires it to refuse. Every write-shaped right the running ABI knows is handled rather than `WRITE_FILE|MAKE_REG` alone — a scope that stops `touch` and allows `ln -s`, `mkfifo` or `mkdir` outside it has a hole that only shows when somebody uses it — with `TRUNCATE` from ABI 3, since truncating a file is a write. The composition root measures the Landlock ABI now instead of reporting 0 unconditionally, so the banner no longer reports `no Landlock` on a kernel that enforces. Four tests, each forking because a domain cannot be left, including one that asserts a second and broader ruleset does not restore what the first denied. **The task stays open**: the second half of its done-condition, zero notification traffic observed through `sys_exit_openat`, is owed.
- **`F2.WS.05` is closed: the supervisor decides by the compiled policy.** `aisme-agentd --policy <file>` parses and compiles at startup with the same `aisme_core::policy` calls `aisme-loaderd --publish` makes, so a policy that compiles for one compiles for the other, and the notify loop evaluates every trapped open against it — `docs/05` §5.3's allow path, which the session-declared prefix list only resembled. **The policy is the daemon's, and that is the security property**: a session that chose what governs it would be choosing whether to be enforced, and `docs/design/02_aisme-run.md` step 3 already has it *receive* the generation. Measured over the shipped three rules, and the column that matters is `asked`: `/etc/hostname` allowed with `0 asked`, `/etc/shadow` **denied with `0 asked`** — nobody was prompted, which is what makes a compiled deny stronger than an escalation nobody answers — and `~/.aws/**` escalated with `1 asked`, the answer obeyed in both directions. `--escalate <prefix>` stays as the shorthand for a session with no daemon policy. Two tests fix it: one evaluates the shipped `deploy/policy/skeleton.aisme` and asserts all three verdicts including the **glob**, which is the rule the abandoned design would have dropped, and one asserts an unbound `${…}` refuses the daemon by name.
- **`docs/10_challenge_cierre_f2.md` — the closing plan for F2, and the review that reshaped it.** It was asked to amplify `F2.WS.09`, `.10`, `.11` and `docs/09` point 6; **its coherence review found that three of the four already are**, in `docs/05` points 9 to 11, so it verifies those against today's tree instead of writing a second specification — the defect `docs/09` point 6 exists to prevent. Five findings, two of which are about the gate itself: **GATE F2 as written would deny nothing**, because its guest lines invoke `aisme run` with no `--trap-openat` and trapping became opt-in after the gate was written (for the measured reason that a filtered session cannot write); and it asks for a compiled `deny` verdict the daemon has no way to reach, because the loader owns the policy and the daemon holds no map. `F0.ASSET.02`'s reference-trace recording is also due — plan `:1360` puts it after `F2.WS.08`, which closed at `df183b6` — and nothing recorded it as owed. Point 2 amplifies the one thing that genuinely lacked it: the session cgroup is released by **`agentd`**, polling `cgroup.events` for the kernel to say the session is empty, because `exec` has no after and the process that created the cgroup is the supervised command by then. Point 3 sets the order — `.11`, the cgroup, `.10`, `.09`, the recording, the gate — and gives the gate's lines the flags F2's design requires rather than giving F2 a policy copy `docs/06` refused.
- **`F2.WS.06` — the walking skeleton asks a human, and the syscall obeys.** `TerminalAdjudicator` implements the frozen `Adjudicator` against §7.3's prompt, in the terminal `aisme run` already owns. Measured end to end: `aisme run --trap-openat --escalate /etc/hostname -- cat /etc/hostname` with `AISME_TERMINAL_ANSWER=d` gives *"Permiso denegado"* and exit 1; with `=1` it gives the file and exit 0; `agentd` reports `1 asked (1 unattended)` in both. **The unattended answer is read once by `aisme run` before `exec`** and carried in `registerSession` — the adjudicator never reads the daemon's environment, which anything able to set a variable there could steer, including the agent being adjudicated, and a test sets the opposite letter ambiently and asserts it is ignored. `I-05`'s never-promptable groups are refused **before** a prompt is composed, because asking about something that cannot be permitted teaches an operator that their answer does not matter. The budget is enforced by the adjudicator, so a caller that forgot to time out still fails closed. Seven tests, five of them against a **real pseudo-terminal**.
- **The escalate class is declared by the session.** `aisme run --escalate <prefix>` carries it in `registerSession`, and the notify loop asks the adjudicator for a path under one and delivers a validated descriptor for everything else. F2's one rule, carried by the session rather than compiled into the daemon: the loader owns the policy and the daemon holds no map (`docs/06` point 3). `F3.PT.02`'s kernel-side trie replaces it with the compiled policy the kernel itself reads.

### Fixed
- **The daemon compiled its policy once, at startup, before any session existed** (`F2.WS.11`). `${workspace}` and `${home}` are facts about **one session** — `Bindings`' own documentation has said so since F1 — so compiling with no bindings left the shipped write-scope rule matching a directory named `$workspace` that no machine has, while the daemon printed `3 rule(s) in force`. A rule that cannot fire is worse than no rule, because the gate that tests it still passes. The daemon parses at startup, where an operator is watching a policy that is not a policy get refused, and compiles **per registration**. `${workspace}` is the scope that session declared, which is the operator's own `--scope` and never the agent's; `${home}` comes from the peer's uid through `getpwuid_r`, because the uid is written by the kernel into `SO_PEERCRED` and cannot be claimed — a registration that sends its own `home` is ignored, and there is a test that says so. A policy that will not bind refuses that session with the variable and the rule named, and leaves the daemon and every other session running. The shipped policy loses both workarounds: `**/.aws/credentials` becomes `${home}/.aws/**`, and `$workspace` becomes `${workspace}`. Measured through the shipped binaries: `/etc/shadow` denied with **0 asked**, the credential rule escalating with **1 asked** against the peer's real home and obeyed both ways, everything else read. `--scope` is JSON-escaped before it goes on the wire, because a directory may legally contain a newline and this protocol frames one object per line.
- **A signal ended the permission prompt's wait and was recorded as a timeout** (`F2.WS.06`). Measured: a budget of 300 ms was given up on in **4.4 ms**, and the escalate class's timeout default is *deny*, so a developer who was about to answer would have been refused. `poll` returns `EINTR` whenever a caught signal arrives and Linux **never restarts it**, not even under `SA_RESTART`, and the wait read that interruption as *the budget ran out* — an absence read as a value. The daemon reaps children, so the signal that triggers it is one the product generates itself. The wait now runs against a deadline and an interruption resumes it with the time that is left; the read that follows is the same class and is resumed the same way. Fixed by `a_signal_does_not_end_the_wait_early`, which delivers `SIGCONT` to the waiting thread with `pthread_kill` five times inside the budget — deterministic, where the defect was originally found as a flake under parallel load.
- **A symbolic link defeated a path-based deny.** Measured: a policy denying a file refused it by its real name and **read the secret through a link to it**. `RESOLVE_NO_MAGICLINKS` stops `/proc/self/root/…` and does not stop an ordinary symlink, which is why one spelling was caught and the other was not. `docs/05` §5.3 had already specified the right order — *"evaluate **the opened file** against the compiled policy"* — and the implementation evaluated the requested spelling and then opened it; inverting those two steps was the entire defect, and it is invisible in every test that asks for a file by its real name. The supervisor now **locates** the file with `O_PATH`, which never blocks and reads nothing so a file the policy is about to refuse is not opened for real and a FIFO cannot hang the supervisor, resolves what the descriptor names, decides on **that**, and reopens **through the descriptor** rather than through the string so nothing is resolved a second time (`I-28`). Recorded in `docs/ai/memory/a-path-is-a-spelling.md`, with the measurement the field puts on the class: 69–98 % of 1,709 real denylists are fragile to an equivalent spelling.
- **`docs/research/01_incidentes_y_defensas_de_agentes_ia.md` — the field record, and the decisions that hang on it.** Two research passes: 32 dated incidents classified as real, disclosed, proof of concept or user report; and the defensive state of the art with its measured failures. The numbers that move the roadmap: **69.0–98.6 % of 1,709 real denylists fragile**; users approve **93 %** of permission prompts and miss **33.4 %** of exfiltration and **35.0 %** of scope violations when they do look; a prompt-injection classifier reaches **60–68 % recall** against an adaptive attacker while four layers together reach 99.7 %; kernel-level monitoring costs **1.9–8.4 %** and **has no third-party evaluation anywhere**. Its Part V carries ten decisions with their evidence, none applied. Its Part VI lists fifteen claims that could not be verified and six gaps where no data exists at all.
- **The enforcement filter named one of the three syscalls that open a path, so it enforced nothing.** Measured against a policy that **denied** a file, in a session running under `--trap-openat`: `open` opened it, `openat` was denied, `openat2` opened it, and the supervisor never saw either of the two. This is not the retry-by-indirection `DT-05` describes — it succeeds **first time**, so nothing is denied and nothing is recorded, and the deny and escalate classes were decoration for any program not going through glibc. glibc's `open()` issues `openat`, which is exactly what made the gap invisible: every ordinary program was trapped and only a deliberate one was not. The filter traps `open`, `openat` and `openat2` now. The three disagree about their arguments, so they are normalised in one place: `open` has no descriptor argument, and `openat2` keeps its flags in a `struct open_how` with a `resolve` field that changes what the path means — so it is trapped and **refused** per `I-28`, because a descriptor opened with the supervisor's own resolution would answer a question the caller did not ask. Measured after: 0 delivered, 3 denied, and GATE F2's five lines still pass unchanged. Recorded in `docs/ai/memory/one-syscall-is-not-one-door.md`, with the same question owed for every other class: a write is six syscalls, an exec is two, a deletion is three.
- **GATE F2's five enforcement lines pass against the configuration that ships.** They were measured in a guest whose daemon runs as `uid 0`, where `CAP_SYS_PTRACE` makes Yama irrelevant, so they measured a different system. Re-run on the host against a daemon with `CapEff 0000000000000000` — **no capabilities at all** — and every line through `sh -c`, therefore through a grandchild: the allowed open is read, the compiled deny refuses with **0 asked** and leaks nothing, the escalation is refused under `d` and permitted under `1` with **1 asked**, and a write outside the scope is denied in kernel with no filter installed while one inside still works. The `asked` column is the one that matters and it could not be read in the guest: a compiled deny asks nobody, so no answer exists to get wrong and no timeout has to expire for it to hold.
- **`aisme run` supervises its own child instead of `exec`ing it, and every descendant is now supervised** (`ADR-09`). The supervisor has to be the session's **ancestor**: Yama grants an ancestor the memory of every descendant and grants a sibling only the process that named it, so a daemon-side supervisor saw the first process of a session and nothing it forked — and 91.1 % of what an agent does is run a subprocess. Measured through the shipped binaries: `sh -c 'cat /etc/hostname'` goes from 2 delivered and **13 denied**, every denial the grandchild's and every one "the path argument could not be read", to 6 delivered and **0 denied**; three shells deep, 10 delivered and 0 denied. **No component holds any capability**, and `PR_SET_PTRACER` leaves the session path entirely. The child is confined after the fork — parent-death signal, Landlock write scope, seccomp filter, listener handed up a socketpair, then `exec` — and the parent answers the notifications, asking the daemon over the new `decideOpen`. That call is also the daemon's only sight of an action now that the loop lives in the session, so it carries the WAL record and the adjudication, and it answers with **whether anybody was asked** beside the verdict, because an escalation answered *deny* and a compiled deny both arrive as `Deny` and only one of them asked nobody. `registerSession` carries no descriptor. The two properties `exec` was chosen for are kept by hand: a death by signal is reproduced **as a signal** rather than as `128+n`, and `PR_SET_PDEATHSIG` makes killing the intermediary kill the session — both measured and both pinned by tests. `CAP_SYS_PTRACE` on the daemon was rejected for the project's own reason: `docs/06` point 3 refused it a writable policy map because that would leave `CapabilityBoundingSet=` decorative, and this is broader than what was refused there.
- **`docs/12_investigacion_guardarrailes_sesiones_ia.md` — what a guardrail for an AI session can actually be, with nine measurements.** The two open questions turned out to be one question asked twice: what can be known about an AI session, by whom, at what altitude. **The intent plane and the action plane are three orders of magnitude apart**: 91.1 % of an agent's tool calls are "run a subprocess" (17 sessions, 13 686 calls), and one such call expands into 1 713 `openat` across 58 programs. So enforcement cannot live at the tool boundary, where 91 % of intents are an opaque shell string, and observation of intent cannot live in the kernel, which never sees a decision. **The spine: Linux hides the actor from an unprivileged observer.** Unprivileged `fanotify` delivers events and reports `pid=0` for every process but the listener itself, which closes it as an attribution route; Yama refuses a sibling the memory of its target's children and grants an ancestor everything at any depth. There are two ways to observe a session's actions and no third: own the process tree, or hold a capability. **A pre-tool hook is the desktop `SdkEnforcer`** the `Enforcer` table already names and no desktop task owns — it receives the full tool input, can deny or force the human prompt, and tightens only. It fails open on timeout and its configuration is reloaded mid-session, so an agent that can write `.claude/settings.json` disables its own guard — which `DT-14` already names and which the session's Landlock scope was measured already denying. Each plane covers exactly the other's blind spot.
- **`aisme declare`, and a hook configuration that is deliberately not installed.** It reads a pre-tool hook's payload on stdin and declares the tool call to the daemon in 1 ms, exiting 0 on every failure path. `deploy/hooks/aisme-hooks.json` is ready to merge by hand: the point of a hook is that the supervised party does not choose it, and that includes an agent editing this repository.
- **The reference-trace recorder, which is everything about `F0.ASSET.02` that does not depend on the owner.** `aisme-agentsim --to-trace <wal-dir> <file>` reads the WAL through `aisme_core::wal`'s replayer and joins each action to the declaration whose process **subtree** contains it. Ancestry and not arrival order: two concurrent tool calls interleave their actions, so "attribute to the most recent declaration" hands half of each to the other while every summary count still comes out right, and the test is built so that defect fails it. The correlation token is deliberately **not** the `toolcall_id` — that id crosses the control socket, and a token the engine can see makes §4.6 measure a join rather than a correlator. An action no declaration explains is kept with token `0` and counted, and an event kind the format has no action for is counted by name, so a partial recording cannot look complete. `--emit-trace` writes §2.22's reference workload scaled, 2 480 actions for thirty minutes, so the whole path is testable with no agent at all. It lives in `aisme-agentsim` rather than `aisme-forensicd`, corrected during implementation: `forensicd` is L3 and cannot name an L4 format, and the stated reason for putting it there was false because the replayer is `aisme-core`'s. Measured end to end through the shipped binaries.
- **A claim of mine in `docs/11` was a ratio read as a conclusion.** It said recording through the seccomp trap "would preserve the counts and destroy the timings the fixture exists for". Measured, the trap adds **17 µs per open**, so a real tool call doing 1 713 opens pays **+29 ms** — a few percent of a second-long command, not a destruction. The weaker claim survives and is the one that matters: the overhead is proportional to open density, so it flattens exactly the short bursty commands the workload is made of.
- **A recorded declaration did not say who declared it, so nothing could ever be joined to it.** Measured in the WAL: `tgid=0 pid=0 kind=ToolCall`. Correlation attributes an action to the declaration made by a process in the action's own ancestry, and an ancestry is walked from a pid — so a declaration without one is an intent recorded beside the actions it claims to explain with no way to reach them. The declaring process is stamped from `SO_PEERCRED` now, which is the kernel's answer and which no client can forge; it is a process and not a thread, so `pid` stays 0 and that is stated rather than left to guess. **No damage today** — nothing correlates yet — but the open path led straight at §4.6's gate and at `F0.ASSET.02`'s recorder, which cannot be built without it. Found while implementing that recorder, which is why it was fixed before a line of it was written.
- **A test stopped being a test while the count went up.** Inserting the case above landed between another test's `#[test]` and its function, so `an_overlong_tool_name_is_truncated_and_says_so` silently became an ordinary function and the suite still reported more tests than before. Both run again, and the workspace total moved by exactly one, which is the arithmetic that catches it.
- **A control-plane test was flaky under a parallel run, and the wait was why.** It waited for the socket *path to exist* — which the listener creates before it accepts, so a socket that is there is not a socket that answers — and it bounded the wait in `yield_now()` calls, a guess measured in scheduler turns rather than in time: a thousand of them pass in microseconds on an idle machine and can elapse before the server thread is scheduled at all when the rest of the suite is running. It retries the **connect** against a wall-clock deadline now, which is the operation that has to succeed. A flaky test is a gate people learn to re-run.
- **`docs/11_challenge_ampliacion_recomendaciones.md` — the two recommendations F2 leaves to the owner, amplified until taking either is execution rather than design.** Five measurements were taken before a word was written, and they split the two points cleanly. **Point 1 survives and its recorded objection falls**: ancestry alone lets a process read a descendant's memory at depth three with no `PR_SET_PTRACER`; killing a supervisor mid-session leaves the child with every later `openat` refused rather than free; and `PR_SET_PDEATHSIG` survives `execve`, restoring exactly the property `F2.WS.08` justified `exec` with. Two things the recommendation had not said are fixed there — the filter and the ruleset go in the child, and the child must not `exec` until the parent holds the listener. **Point 2 falls**: a session record carries 838 tool calls and no actions, four of the trace format's five action kinds are things only a kernel sees, and the session's shape is forty times sparser than §2.22's normative workload and almost entirely one action kind. What replaces it is the mechanism already designed, `declareToolCall` joined to sensed actions by process subtree, and most of the recorder can be built before either open question is answered. A coherence pass over both points names the route somebody will propose — recording through the seccomp trap, which needs no BPF at all — and why it fails: it costs 46.6 µs against 1.8 µs and would preserve the counts while destroying the inter-arrival timings the fixture exists for.
- **GATE F2 ran, and its output is in `STATE.md` verbatim.** Four host lines and five enforcement lines in **one** guest boot rather than four: `test-skeleton` at 72 ms, the five verdicts in a 6.8 guest, `verify-budgets --profile skeleton` with every measured figure inside its ceiling, and `bench-t0` over 100 000 samples. **The first run reported PASS and the PASS was false** — the fourth check this phase has produced that reported a property it did not test, and this one was written the same day as the fixes for the other three: the tilde did not survive the wrapper so the escalate line tested a literal path, only the *deny* answer was exercised while everything was being denied for an unrelated reason, the `asked` column was never read, and the Landlock line carried `--trap-openat` so its denial could have been the supervisor's. Rewritten so each assertion can fail, the five lines pass for real. **The gate does not close F2**: the guest daemon runs as uid 0 while the shipped unit runs as `User=aisme` with an empty capability set, so every line passes on a configuration the product does not ship — which is worse than a failing gate, because it reports the properties of a different system. The plan's gate block is corrected in all four ways.
- **A policy path starting with `~/` was a rule that could never fire, and the shipped policy had one.** `cat ~/.aws/credentials` under the skeleton policy was answered with **0 asked**: the tilde is expanded by a shell, so the kernel is asked for `/home/<user>/.aws/credentials` and a pattern still carrying one matches nothing. GATE F2's third enforcement line would have passed by escalating nothing, and an assertion in `test-skeleton` was vacuous for the same reason — it handed the policy the literal string no process ever opens. The fix is one guard in the compiler: a path pattern beginning with `~/` is refused by name, in both `path_glob` and `path_under`, with the reason and the alternative. A tilde anywhere else stays an ordinary character, and a test asserts that a file named `report~` still compiles. Everything that taught the wrong form is corrected: the canonical fixture and the grammar's example in the plan now read `${home}/…`. The skeleton's rule becomes `**/.aws/credentials` — one `**`, which is the compiler's budget — and was measured escalating against a real resolved home path with the answer obeyed both ways.
- **The write scope denied `/dev/null`, which breaks essentially every benign workload.** The first supervised shell that redirected anything reported "cannot create /dev/null: Permission denied" on a command that wrote nothing anywhere, and this project holds that a false positive is as serious as a missed detection. The non-storage character devices are granted explicitly — `/dev/null`, `/dev/zero`, `/dev/full`, `/dev/random`, `/dev/urandom`, `/dev/tty` — one by one and never `/dev` wholesale, which also holds `/dev/mem` and every block device. Each stores nothing, so a write to it exfiltrates nothing and mutates nothing that survives the call. Fixing it uncovered a second rule: a `PATH_BENEATH` rule on a **non-directory** takes only file rights, and a directory-only right such as `MAKE_REG` makes `landlock_add_rule` answer `EINVAL` — which refused the whole ruleset and stopped the session starting rather than confining it. The access is computed per path now. A test asserts the devices stay writable **and** that the scope still denies, in the same child, because a ruleset that had stopped denying would pass the first half on its own.
- **`gate --level pr` reported `FAIL` on every machine, and always would have.** The runner invokes each member with no arguments, and `vm up`, `vm run` and `vm probe` each need an image name it has no way to choose — so all three printed their usage, exited 1, and were counted as failures. A gate that cannot pass is decoration. The three verbs are no longer automatic gate members; they remain Annex H commands and the plan's `GATE F2` block calls them explicitly with the image the phase is measured against. `gate --level pr` now reports 11 PASS, 0 FAIL, 2 SKIP and 47 PENDING.
- **Every supervised agent was classified as the human principal.** `in_session_cgroup` looked for `/aisme.slice` and `/aisme-session-`; `aisme run` creates `aisme-<16 hex>` and the deployed unit delegates a `sessions` subgroup, so neither pattern matched anything that exists and the answer was always "not in a session". No damage today — `setPolicy`, `manageGrant` and `manageSuppression` are the three methods behind that class and none is dispatched yet — but it was an open path straight at `F7.PS.08`. The patterns now match the names sessions are actually given, which moves the classification in the conservative direction.
- **A daemon that could not compile its policy exited 0.** `aisme-agentd --run … --policy <broken>` printed the failure and returned, so it supervised nothing while reporting success to everything that reads only the exit status — the gate's guest script, a unit file, an operator's `&&`. This is the exact outcome the startup compile exists to prevent, and the code's own comment claimed it was prevented. Every argument and startup error path in `main` now exits non-zero, following the convention `measure-idle` already set.
- **Three errors in the implementation plan, one of which would have made GATE F2 pass without enforcing anything.** Its guest lines invoked `aisme run` with no policy, and `aisme run` installs no seccomp filter without one — so `cat /etc/shadow` would have printed the file and exited 0 while the gate reported the property it had not tested. Every guest line now carries `--policy`, and the block says why: a filter traps every `openat` and `CONTINUE` is forbidden for a path-bearing syscall (`I-28`), so a session under one is answered open by open and a session without a policy would be answered by nobody. The block distinguishes the three verdicts by **mechanism** — an allow arriving as a descriptor the supervisor opened, a **compiled deny** refused without anybody being asked, and an escalation whose answer is obeyed — because a gate that cannot tell a compiled deny from a timed-out prompt lets the first silently become the second. §3.2's composition line showed `Engine::new(sensors, enforcers, adjudicators, sink)`, a signature the code has never had, hiding that the enforcers live on the control thread — an engine that owned an adjudicator would put a human on the T0 path.
