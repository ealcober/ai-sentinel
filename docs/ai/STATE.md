The obstruction is the BTF `bpf-linker 0.11` emits against what this aya reads; mixing sections was a consequence, not the cause. **Superseded (kept for the record):** `BPF_MAP_TYPE_ARRAY_OF_MAPS` exists in `aya-ebpf 0.2.1` only as a **BTF map** (`#[btf_map]`, `.maps` section), while the `F2.WS.01` program's maps are `#[map]` (legacy `maps` section). **WSL interop is gone from this distribution** (`F0.WSL.02`): `cmd.exe` and `wsl.exe` fail with `exec format error` because `/proc/sys/fs/binfmt_misc/` no longer holds the `WSLInterop` entry. **Cause, half verified**: binfmt_misc is one kernel-wide table, and a guest's *termination* clears it for every distribution — four losses here. Three followed the systemd guest stopping, as [rancher-desktop#10049](https://github.com/rancher-sandbox/rancher-desktop/issues/10049) describes (masking `systemd-binfmt.service` does not help). The fourth and fifth followed a **first-time probe** in a non-systemd guest — the fifth with that guest still running and every other guest either held open or already stopped with the table intact — while the splitting run showed that neither an idle termination nor the probe script plus an explicit terminate clears it on a repeat run. The replay settled it (report, *WSL2 images*): `apt` is falsified; losses 1, 4 and 5 are the **first boot of a freshly imported guest with its `wsl.conf` applied** — a trivial session with no script loses the entry three seconds later, and every later boot of that guest is harmless — while 2 and 3 are the systemd guest's `ExecStop --unregister` chain and termination. What WSL's `init` does on that first boot stays unexplained, inside WSL 2.7.8.0. **What unblocks it**, the owner's action, either one:

```bash
sudo sh -c 'echo ":WSLInterop:M::MZ::/init:PF" > /proc/sys/fs/binfmt_misc/register'
```

or a new session in this distribution opened from Windows. A third option, the owner's to take: a sudoers line for that one command (`<user> ALL=(root) NOPASSWD: /bin/sh -c echo \:WSLInterop\:M\:\:MZ\:\:/init\:PF > /proc/sys/fs/binfmt_misc/register`) would let `vm` re-register after every guest run instead of the owner doing it by hand each time. **What holds so far**: `vm probe wsl2-<systemd variant>` keeps the guest open with a detached `sleep infinity` session and the entry survived that probe; both guests are currently registered, the systemd one held open (`ps` shows `wsl.exe -d aisme-wsl2-ubuntu-24.04 -- sleep infinity`). **What `vm up wsl2-*` now does**: it takes that first boot itself, waits five seconds, and re-registers the entry with `sudo -n` — or prints the line above and fails, so no later step inherits a dead interop; `vm probe` checks the same after every guest run. The sudoers line is what makes it hands-off. Prediction for the next `vm up` of a fresh import: the entry goes at its first boot and `vm up` says so; every `vm probe` after it leaves it alone.

## Notes for whoever picks this up

- **Plan Part II is the most valuable artefact here.** It exists specifically to stop the research's rejected designs from being re-implemented by a well-meaning contributor. Read it before writing kernel code. The precedence rule is in Plan §7.6.
- **Windows is served by WSL2** (ADR-02). The native driver spec lives in **Annex F** marked `[POST]` — do not implement it. Keep the `Sensor`/`Enforcer`/`Adjudicator` trait boundaries (§3.2); they are what makes that decision cheaply reversible.

- **Two primitives make tier L2 real**: Landlock (in-kernel file deny) and `BPF_CGROUP_INET*_CONNECT` (in-kernel network deny). Both work without a reboot and without BPF-LSM, which matters because WSL2 — the Windows strategy — is L2 by default. **Landlock is confirmed on WSL2** (`F0.WSL.01`: ABI 7, `EACCES` outside the allowed path under a real ruleset); the matrix kernels are `F0.VM.02`, and the cgroup hook still needs a loader (`F0.VER.16`).
